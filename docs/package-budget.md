# 代码质量扫描优化

保留页面布局、文字、字体、交互和地图轮廓。针对微信开发者工具报告的三项建议：

1. `app.json` 启用 `lazyCodeLoading: "requiredComponents"`。
2. JPEG 使用优化编码，保留每张照片/纹理的像素尺寸；所有图片低于 200,000 字节。图片是有损重新编码，不声称像素值完全相同。
3. 地图采用 delta/base36 无损存储，JS 文件从 380,980 字节降至 164,819 字节。运行时解码后已与压缩前所有区域、所有环、所有坐标逐项 deepEqual 对比，完全一致。
4. 明确从打包中排除开发用 `.eslintrc.js`。已有 docs/tests/scripts 等排除配置保留。

`npm run check` 会检查按需注入配置、运行源码清单低于 1,400,000 字节、单个媒体文件不超过 200,000 字节，并继续校验路由、图片和 WXML 绑定。源码预算保留部分编译开销余量；微信工具扫描的是最终编译主包，仍需在工具里点击重新扫描确认，不能把源码体积等同于已通过微信扫描。


第二轮复查：运行资源已达标，但 docs/runtime-review 下仍有两张截图超过 200,000 字节。已对所有较大的预览截图重新编码，保持尺寸不变。资源体积检查现覆盖整个项目，包括排除打包的文档截图，而不只检查运行资源。
