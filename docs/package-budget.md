# v2.2.1 — 同时约束资源总量与单文件大小

之前仅约束单个媒体文件小于 200 KB，没有降低包内媒体累计大小。这不足以解释或消除微信工具持续报告的资源项未通过。官方教程页面在本次云环境被代理拒绝访问，因此这里不冒充已核实工具内部规则；改为同时满足两种统计口径。

本版：

- 从整个项目移除 10 张大体积演示图片和文档中的预览截图。全部仍保存在 GitHub 已发布的不可变提交 `52787f34af1c905dc8381d2e843020f27ef3481d`，不是丢弃原图。
- 演示图片通过 `utils/media.js` 的固定版本 HTTPS 地址按需加载，优先 jsDelivr，加载失败尝试同一提交的 GitHub 原始文件。
- 所有 10 张远程图片已逐个完成 HTTP 200、内容类型及 SHA256 与原本地图片一致性验证。证据在 `remote-media-verification.json`。
- 本地仅保留 6 个小图标/纹理文件，总计 21,591 字节，既小于累计 200 KB，也满足每个文件小于 200 KB。
- 运行源码约 0.39 MB。按需注入和原有代码压缩配置保留。
- `npm run check` 对整个项目的媒体累计大小设置 **100,000 字节**上限，同时检查每个文件 <=200,000 字节，防止再次只验证单张大小。

## 使用影响

演示大图需要联网。没有关闭 URL、TLS 或证书校验。远程网络在不同设备/地区的可达性需要在微信工具与真机确认，云端成功不能证明所有用户设备都能访问。

用户上传的 wxfile 本地照片不上传、不移出、不替换；只迁移已知 `/assets/...` 演示图片路径。没有新增账号、密钥或云存储要求。

页面布局、样式、字体、地图轮廓和交互保持不变，Profile 页底部显示 `v2.2.1` 用于确认打开的确实是新目录。

## 更新时必须使用新目录

ZIP 不能自动删除旧目录中的文件。把新版覆盖进旧目录可能保留旧 assets 和 docs 大图，仍被工具统计。应解压到全新目录，再导入直接包含 app.json 的那层。

最终结果应在微信开发者工具里重新编译和重新扫描确认；本地预算检查不是官方扫描通过凭据。
